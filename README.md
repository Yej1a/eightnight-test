# 笔试协作记录

这个仓库用于整理一次笔试过程中的工作材料，方便在允许的前提下向他人展示协作方式、过程记录与最终产出。

- `deliverables/常驻7日签到福利系统开发策划文档.md`
- `deliverables/常驻7日签到福利系统开发策划文档.docx`
- `处理调优过程.docx`

## 如何查看项目

如果你是第一次打开这个仓库，建议按下面顺序查看：

1. 先看 `README.md`
2. 再看 `deliverables/常驻7日签到福利系统开发策划文档.docx`
3. 如果想看规则推导过程，再看 `deliverables/常驻7日签到福利系统策划文档.md`
4. 如果想看协作与决策记录，再看 `docs/协作流程.md` 和 `docs/决策记录.md`
5. 如果想看自动化校验思路，再看 `deliverables/signin_7day_cycle_validator.py` 与 `deliverables/常驻7日签到自动化脚本思路.md`

推荐查看方式：

- 需要正常文档格式时，直接打开 `deliverables/常驻7日签到福利系统开发策划文档.docx`
- 需要在线快速浏览时，优先看 Markdown 文档
- 需要理解实现与校验思路时，再看脚本和说明文件

## 使用前说明

- 仅在笔试规则允许使用 AI 协助、允许保留或展示过程材料时使用本仓库。
- 如题目包含保密内容，请在上传 GitHub 前先做脱敏处理。
- 对外展示时，优先展示方法、流程与决策，不直接暴露不适合公开的题面或答案细节。

## 仓库结构

- `docs/协作流程.md`：协作方式、推进节奏与交付方式
- `docs/决策记录.md`：关键判断、假设与调整记录
- `deliverables/`：最终交付材料或可提交内容

## 推荐工作流

1. 将原始题目材料放入本地目录，并先确认使用规则。
2. 在 `docs/决策记录.md` 中记录题目目标、约束和关键假设。
3. 开始解题时，持续把关键过程整理进文档，而不是事后回忆补写。
4. 最终把可公开内容放进 `deliverables/`，并检查是否需要脱敏。
5. 再提交到 GitHub，作为可分享链接。

## 对外展示建议

- README 只讲背景、方法和目录，不堆过多过程细节。
- 详细过程放在 `docs/`，让别人既能快速浏览，也能按需深入。
- 如果最终要给面试官或同事看，建议附一段简短说明：哪些内容是原始题面，哪些是你的解法，哪些是协作记录。
