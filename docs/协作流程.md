# 协作流程

## 目标

在不偏离题目要求的前提下，用可复盘、可展示的方式完成笔试任务，并保留清晰的过程记录。

## 角色分工

- 你：提供题目、确认约束、做最终判断与提交
- 我：协助拆解需求、梳理方案、补代码或文档、校验链路完整性

## 推进方式

1. 读取原始需求
2. 提炼目标、输入、输出、约束
3. 在存在关键歧义时再澄清；否则基于最合理假设继续推进
4. 给出最小完整方案，而不是临时拼补丁
5. 实施并校验结果
6. 将关键判断沉淀到文档，便于后续展示

## 每轮协作的记录模板

### 1. 当前问题

- 题目要求：
- 已知约束：
- 待确认点：

### 2. 我的处理

- 输入：
- 处理流程：
- 状态变化：
- 输出：
- 上下游影响：

### 3. 结论

- 采用方案：
- 关键原因：
- 风险与未验证项：

## 展示口径

- 对外优先展示解题思路、结构化分析和决策过程
- 不把推测写成已确认事实
- 不展示未经允许的题面、账号、公司内部信息或敏感数据
