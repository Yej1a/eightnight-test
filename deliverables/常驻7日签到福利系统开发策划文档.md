# 常驻 7 日签到福利系统开发策划文档

## 1. 文档定位

### 1.1 背景

本功能用于在已上线游戏项目中新增一个常驻七日签到福利系统。玩家每日登录后可领取当日签到奖励，补齐 7 个签到槽位后获得阶段大奖。功能长期开放，作为常驻活跃与留存模块存在。

### 1.2 文档用途

本文件作为开发落地用策划文档，目标是让产品、客户端、服务端、测试、运营对以下内容形成统一口径：

- 核心玩法规则
- 页面展示与交互规则
- 服务端状态与接口约定
- 配置与运营规则
- 特殊状态、异常与补偿机制
- 验收与测试口径

### 1.3 默认前提

- 项目已具备登录、角色、背包、邮件、活动配置、基础发奖能力
- 本功能为常驻福利，不是新手一次性签到
- 本功能面向全量玩家开放，不设置等级或章节门槛
- 默认按“角色 + 区服”维度参与，同账号下不同角色、不同区服不共享进度

## 2. 功能摘要

### 2.1 功能目标

- 提升日常登录活跃
- 提供稳定常驻福利
- 通过补签提供轻量付费转化点

### 2.2 一句话规则

玩家每个服务器日最多获得 1 个新的免费签到槽位；未领取的历史槽位在次日转为可补签；当本轮 7 个槽位全部完成后，阶段大奖解锁并可领取；若未主动领取，则系统在下一轮开启前自动补发。

## 3. 术语与核心定义

### 3.1 术语

| 术语 | 含义 |
| --- | --- |
| 轮次 | 一轮固定包含 7 个签到槽位 |
| 槽位 | 单日签到单元，每轮共 7 个 |
| 正常签到 | 玩家对当日免费槽位执行领取 |
| 补签 | 玩家消耗钻石补领历史漏签槽位 |
| 阶段大奖 | 当前轮次 7 个槽位全部完成后解锁的独立奖励 |
| 日切 | 按服务器时区每日 `00:00` 刷新状态 |
| 轮次快照 | 玩家进入当前轮次时冻结的奖励、价格、发奖策略版本 |

### 3.2 参与维度

- 唯一参与维度：`roleId + serverId + activityId`
- 同账号切换角色、切换区服时，不共享轮次、补签资格和大奖状态

## 4. 核心玩法规则

### 4.1 基础规则

- 每轮固定 7 个槽位
- 每个服务器日最多新增 1 个免费签到槽位
- 漏签不清空整轮进度
- 历史漏签槽位可通过付费补签完成
- 阶段大奖不是第 7 天自动发，而是 7 个槽位全部完成后才解锁
- 单轮完成后，当天停留在完成态，下一次日切后才进入下一轮

### 4.2 日切规则

- 统一使用服务器时区
- 每日 `00:00` 执行日切
- 日切只推进 1 个新槽位，不补发历史免费资格
- 玩家未登录期间也照常推进开槽
- 单轮最多推进到第 7 槽位，不会因为长时间未登录而无限积压免费签到次数

### 4.3 槽位推进规则

1. 玩家首次进入功能时初始化第 1 轮
2. 初始化后第 1 个槽位为当日可签到
3. 玩家正常签到后，该槽位完成
4. 当日未领取的槽位，在次日日切后转为可补签
5. 每次日切至多新增 1 个新的免费槽位
6. 当 7 个槽位全部完成后，本轮完成，阶段大奖解锁
7. 阶段大奖主动领取或系统自动补发完成后，本轮结算闭环
8. 下一次日切后开启下一轮第 1 槽位

### 4.4 正常签到规则

- 仅当存在 `claimable` 槽位时可执行
- 每个自然日仅允许正常签到 1 次
- 正常签到不消耗资源
- 正常签到成功后立即发放对应日奖励

### 4.5 补签规则

- 仅针对历史已开放但未领取的槽位
- 每个漏签槽位最多补签 1 次
- 补签消耗钻石
- 补签与正常签到不冲突，同一天可同时发生
- 补签完成后立即发放对应日奖励

### 4.6 阶段大奖规则

- 阶段大奖与第 7 个槽位日奖励是两笔独立奖励
- 达到第 7 天不代表大奖可领取
- 只有本轮 7 个槽位全部完成后，阶段大奖状态变为 `claimable`
- 若本轮完成当日玩家未主动领取，系统在下一次日切开启新轮次前自动补发
- 活动关闭时，所有已满足资格但未领取的阶段大奖统一自动补发

## 5. 状态设计

### 5.1 槽位状态

| 状态值 | 含义 | 可执行操作 |
| --- | --- | --- |
| `locked` | 未解锁 | 无 |
| `claimable` | 当日免费可签 | 正常签到 |
| `claimed` | 已正常签到 | 无 |
| `makeup_claimable` | 历史漏签，可补签 | 补签 |
| `makeup_claimed` | 已补签 | 无 |

### 5.2 阶段大奖状态

| 状态值 | 含义 |
| --- | --- |
| `locked` | 本轮 7 槽未全部完成，不可领取 |
| `claimable` | 本轮 7 槽已全部完成，可主动领取 |
| `claimed` | 已主动领取或自动补发完成 |

### 5.3 玩家轮次状态

| 字段 | 说明 |
| --- | --- |
| `playerId` | 玩家 ID |
| `roleId` | 角色 ID |
| `serverId` | 区服 ID |
| `activityId` | 活动 ID |
| `currentRoundNo` | 当前轮次编号 |
| `roundStartDate` | 当前轮次开始日期 |
| `roundStatus` | `in_progress` / `completed` |
| `slots[1..7]` | 当前轮次槽位状态集合 |
| `todayClaimed` | 今日是否已正常签到 |
| `lastRefreshDate` | 最近一次日切刷新日期 |
| `grandRewardStatus` | 大奖状态：`locked` / `claimable` / `claimed` |
| `roundConfigVersion` | 当前轮次配置快照版本 |
| `settlementStatus` | 结算状态：`normal` / `pending_compensation` |

## 6. 前端需求

### 6.1 入口规则

- 功能入口常驻于福利页或活动集合页
- 若大厅已有福利 Icon，可同步挂接入口
- 红点默认仅提示“存在免费可签到槽位”
- 特例 1：阶段大奖已处于 `claimable` 但未领取时，入口持续显示红点
- 特例 2：若第 7 天已开启，且玩家只差补签历史漏签即可解锁大奖，且当前钻石余额足以完成剩余补签，则显示红点提示
- 除上述场景外，仅存在补签机会但无免费可领时，不显示红点

### 6.2 页面展示内容

- 当前轮次
- 7 个槽位奖励
- 当前完成进度
- 第 7 天奖励与阶段大奖
- 阶段大奖状态与锁定原因
- 当前可补签槽位数
- 单次补签价格
- 玩家当前钻石余额是否足以完成剩余补签
- 规则说明文案

### 6.3 页面状态

| 页面状态 | 条件 | 展示重点 |
| --- | --- | --- |
| 未开启 | 活动未到开启时间 | 展示未开启说明 |
| 进行中且今日可签到 | 存在 `claimable` 槽位 | 高亮签到按钮 |
| 进行中但仅可补签 | 无 `claimable`，有 `makeup_claimable` | 展示补签按钮 |
| 第 7 天已开启且大奖待补签解锁 | 第 7 槽已开放，大奖仍锁定，存在历史漏签 | 展示锁定原因与补签提示 |
| 本轮完成待领大奖 | 7 槽全部完成，大奖为 `claimable` | 展示大奖领取按钮 |
| 本轮完成 | 大奖已 `claimed` | 展示完成态 |
| 已关闭 | 活动关闭 | 页面只读，不可操作 |

### 6.4 交互规则

- 所有资格判断以服务端返回为准
- 签到、补签、领奖按钮点击后必须防重复提交
- 操作成功后立即刷新状态
- 奖励走邮件补发时，前端需明确提示
- 若客户端缓存配置版本过旧，需按服务端返回结果刷新页面

## 7. 服务端需求

### 7.1 核心配置对象

#### `SignInActivityConfig`

| 字段 | 说明 |
| --- | --- |
| `activityId` | 活动 ID |
| `openTime` / `closeTime` | 活动开启/关闭时间 |
| `timezone` | 服务器时区 |
| `cycleLength` | 固定 7 |
| `rewardGroupId` | 日奖励组 ID |
| `grandReward` | 阶段大奖配置 |
| `makeupEnabled` | 是否允许补签 |
| `makeupCostType` | 补签货币类型 |
| `makeupCostValue` | 单次补签价格 |
| `unlockRule` | 开放规则 |
| `deliveryPolicy` | 发奖策略 |
| `redPointPolicy` | 红点策略 |
| `progressScope` | 进度归属范围，默认角色+区服 |
| `roundConfigFreezePolicy` | 当前轮次配置冻结策略 |
| `grandRewardUnclaimedPolicy` | 大奖未领处理策略 |
| `activityCloseSettlementPolicy` | 活动关闭结算策略 |

### 7.2 轮次配置快照规则

- 玩家进入当前轮次时，固化以下配置到快照：
- 日奖励组
- 阶段大奖配置
- 补签价格
- 发奖策略
- 快照只影响当前轮次
- 运营热更仅对新轮次生效

### 7.3 接口设计

#### `GET /signin/status`

返回至少包含：

- 活动开启状态
- 当前轮次
- 7 槽状态
- 今日是否可正常签到
- 可补签槽位列表
- 补签价格
- 当前钻石余额是否足够完成剩余补签
- 阶段大奖状态与锁定原因
- 红点状态
- 当前轮次配置版本

#### `POST /signin/claim`

用途：

- 处理当日免费签到

约束：

- 仅允许处理当前 `claimable` 槽位
- 必须幂等
- 重复点击只能成功一次

#### `POST /signin/makeup`

用途：

- 处理历史漏签补签

入参：

- `slotIndex`

执行顺序：

1. 校验活动开启
2. 校验槽位可补签
3. 校验余额
4. 生成补签订单与扣费流水
5. 扣除钻石
6. 发放该槽位奖励
7. 若补齐 7 槽，则将阶段大奖改为 `claimable`
8. 更新状态并写入流水

约束：

- 不能出现已扣费但状态不可恢复
- 同一槽位不能重复补签
- 若扣费成功后，背包发奖和邮件补发都失败，需进入 `pending_compensation`

#### `POST /signin/grand-reward/claim`

用途：

- 领取阶段大奖

约束：

- 仅当 `grandRewardStatus = claimable` 时可执行
- 必须幂等
- 发放失败时进入补偿队列
- 不允许因重复请求重复发奖

#### `GET /signin/records`

用途：

- 客服、运营、排查问题

返回至少包含：

- 当前轮次信息
- 每个槽位领取方式与时间
- 阶段大奖领取状态与时间
- 当前轮次配置版本
- 生效奖励组
- 补签订单与扣费流水
- 发奖记录
- 邮件补发记录
- 补偿任务状态

## 8. 发奖与一致性规则

### 8.1 发奖优先级

- 优先直发背包
- 背包失败则走邮件补发
- 背包与邮件都失败时，创建补偿任务

### 8.2 流水要求

- 每次日奖励发放生成唯一奖励流水
- 每次阶段大奖发放生成独立奖励流水
- 每次补签扣费生成独立订单号与货币流水号
- 每次自动补发大奖生成独立补偿流水号

### 8.3 幂等与串行

- `claim`、`makeup`、`grand-reward/claim` 全部必须幂等
- 同一玩家的签到相关请求必须串行处理
- 同一补偿任务必须幂等执行

### 8.4 一致性底线

- 槽位奖励成功，只能改变大奖资格，不等于大奖已发
- 已成功发放的日奖励不能因后续大奖失败而回滚
- 补签扣费成功后，任何下游失败都不得丢失订单上下文

## 9. 运营与后台需求

### 9.1 必需运营能力

- 活动开关配置
- 活动时间配置
- 日奖励配置
- 阶段大奖配置
- 补签价格配置
- 区服/分组投放配置
- 前台文案与资源位配置
- 玩家状态查询
- 奖励流水查询
- 补偿任务查询与重试
- GM/客服手动补发
- GM/客服重置轮次、修复大奖状态、修复槽位状态

### 9.2 热更规则

- 正在进行中的轮次不允许直接热更奖励、价格、发奖策略
- 热更默认只对新轮次生效
- 若必须影响当前轮次，只能通过显式重置轮次或重置活动实现

### 9.3 后台干预规则

- 后台补发、修复状态与前台请求必须串行化
- 后台干预后需刷新玩家缓存
- 所有 GM/客服操作必须保留审计日志

## 10. 特殊状态与边界情况

### 10.1 跨日未领取

- 当日未领取的免费槽位，次日转为可补签
- 不允许保留为免费资格

### 10.2 当日已签到但历史仍有漏签

- 当日不能再次正常签到
- 历史漏签仍可补签

### 10.3 第 7 天已到但大奖未解锁

- 第 7 槽位开放不代表大奖可领
- 仍有历史漏签时，大奖必须锁定

### 10.4 大奖已可领取但玩家未领取

- 不阻塞下一轮开启
- 下一次日切前自动补发
- 自动补发失败进入补偿队列

### 10.5 活动关闭

- 活动关闭后不再允许签到、补签、主动领大奖
- 已满足资格但未领取的大奖，在关闭结算时自动补发
- 已进入邮件的奖励仍按邮件生命周期领取

### 10.6 长时间未登录

- 未登录期间照常推进开槽
- 回归时历史已开放未领取槽位统一转补签
- 不补发中间所有天数的免费资格

### 10.7 跨日请求

- 请求发起时和落库时跨越 `00:00`，以服务端最终校验结果为准
- 前端缓存状态不能作为最终结算依据

### 10.8 余额不足

- 免费签到红点不依赖余额
- “补签即可解锁大奖”红点默认要求余额足够补齐剩余漏签
- 余额不足时不在入口强提示，但面板需展示差额

### 10.9 扣费成功但发奖失败

- 补签扣费成功后，如果直发与邮件都失败，进入 `pending_compensation`
- 补偿完成前不得把该次操作视为彻底成功

### 10.10 账号与区服切换

- 同账号切换角色或区服时，不共享当前轮次和大奖资格

## 11. 测试与验收

### 11.1 核心验收场景

1. 新玩家首次进入，正确初始化第 1 轮第 1 槽位
2. 连续 7 天正常签到，正确发放 7 次日奖励，并获得阶段大奖领取资格
3. 本轮完成后，当天不立即开启下一轮，下一次日切才开启
4. 漏签后继续登录，历史槽位转为可补签，当前天槽位正常开放
5. 同一天先正常签到再补签历史槽位，状态正确
6. 多个漏签槽位连续补签，扣费与发奖一致
7. 第 7 槽位开启但仍有漏签时，大奖保持锁定
8. 补齐最后一个漏签后，大奖状态正确变为可领取
9. 只差补签即可解锁大奖且余额足够时，红点提示正确
10. 大奖领取成功后不可重复领取
11. 背包满时奖励正确转邮件
12. 多端并发签到，仅一个请求成功
13. 多端并发领大奖，仅一个请求成功
14. 日切前后请求边界正确
15. 大奖已可领取但未主动领取时，系统自动补发成功，且不阻塞新轮次
16. 活动关闭后，已满足资格未领的大奖被自动补发
17. 热更奖励组与补签价格后，仅新轮次使用新配置
18. 同账号切换角色或区服，不串用签到进度
19. 补签扣费成功但下游全失败时，正确进入补偿队列并最终补偿成功
20. GM/客服后台重置与补发不与前台请求重复结算

### 11.2 非功能关注点

- 状态一致性
- 并发安全
- 发奖补偿能力
- 流水可追溯性
- 埋点完整性

## 12. 默认取值

- 日切时间：服务器时区每日 `00:00`
- 轮次长度：7 天
- 补签价格：固定单价
- 进度归属：角色+区服
- 大奖未领取处理：下一次日切开启新轮次前自动补发
- 活动关闭处理：自动补发已满足资格未领取的大奖
- 红点默认策略：免费签到提示；大奖待领提示；满足特例且余额足够时提示

## 13. 开发拆解建议

1. 先实现配置模型、轮次快照、玩家状态模型
2. 实现日切刷新、正常签到、补签、大奖领取、自动补发
3. 实现发奖流水、扣费订单、补偿任务
4. 实现前端入口、面板状态、红点逻辑
5. 实现运营配置、后台查询与 GM 修复工具
6. 最后补齐埋点、测试用例与自动化校验脚本
